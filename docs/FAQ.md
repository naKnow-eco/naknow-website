# FAQ update guide

The FAQ section lives on the home page, between **Partners** and **Contact**.

## Source of truth

FAQ content is managed in **Loco** (`https://localise.biz/naknow/naknow`).  
The local file `i18n/locales/en-US.json` is generated by `pnpm locales`, so it will be overwritten on the next fetch. Always update Loco first.

## Files involved

| File | Purpose |
|------|---------|
| `i18n/locales/en-US.json` | Generated FAQ text content (do not edit directly). |
| `scripts/faq-locize-import.json` | Ready-to-import JSON file for the initial FAQ content. |
| `app/components/home/modules/faq.vue` | Main FAQ section layout. |
| `app/components/home/components/faq/item.vue` | Single question/answer accordion item. |
| `app/domains/navigation/constants/nav-links.ts` | Header navigation link (`#faq`). |

## Structure in Loco

Each FAQ entry follows this nested JSON shape, matching the rest of the site (`title`/`values` style):

```json
{
  "faq": {
    "title": "Frequently Asked Questions",
    "sections": [
      {
        "title": "Section title",
        "questions": [
          {
            "question": "Question text?",
            "answer": {
              "text": [
                "Intro paragraph."
              ],
              "items": [
                "First list item",
                "Second list item"
              ]
            }
          }
        ]
      }
    ]
  },
  "header": {
    "links": {
      "faq": "FAQ"
    }
  }
}
```

Rules for an `answer` object:
- `text` is an **array of strings**. Each string is rendered as a paragraph.
- `items` is an **array of strings**. Each string is rendered as a bullet list item.
- Either `text` or `items` can be omitted. Both can be omitted, but an empty answer is not useful.
- This matches the pattern used elsewhere in the site (e.g. `home.goal.open.title` + `home.goal.open.values`).

## Option 1: Import a JSON file into Loco (recommended for bulk updates)

1. Sign in to https://localise.biz/naknow/naknow.
2. From the dashboard, click the **upload icon** to open the import wizard.
3. Select `scripts/faq-locize-import.json` (or your updated version of it).
4. Confirm the format: choose **i18next v4** (`format=i18next4`).
5. Select **Asset IDs** as the source and **en** as the target language.
6. Use the merge settings to avoid deleting existing keys.
7. Save and publish.

Docs: https://localise.biz/help/formats/importing#ui and https://localise.biz/help/formats/importing/json

## Option 2: Edit directly in the Loco dashboard

1. Go to https://localise.biz/naknow/naknow.
2. Select the **en** locale.
3. Add or edit the keys under `faq.*` and `header.links.faq`.
4. Use the `answer.text` and `answer.items` arrays as shown above.
5. Save and publish.

## After updating Loco

Regenerate the local locale file:

```bash
pnpm locales
```

Then build the site:

```bash
pnpm generate
```

## Adding a new section

Add a new object to `faq.sections` with a `title` and a `questions` array. No code changes are needed.

## Adding a new language later

If the site supports more languages in the future, translate the same `faq.*` and `header.links.faq` keys in each new locale inside Loco.

## Updating the import file

If you want to keep `scripts/faq-locize-import.json` as a reusable import template, edit it to match the Loco structure above and re-import it whenever the FAQ changes.

# Events update guide

The Events section lives on the home page, between **Partners** and **FAQ**. It lists links to LinkedIn posts for naKnow events and automatically splits them into **Upcoming** and **Past** based on each event's date.

## Source of truth

Events text labels are managed in **Loco** (`https://localise.biz/naknow/naknow`).  
The local file `i18n/locales/en-US.json` is generated by `pnpm locales`, so it will be overwritten on the next fetch. Always update Loco first.

Event data (date, title, LinkedIn URL) lives in `app/domains/events/constants/events.ts`. Edit this file directly to add, remove, or change events.

## Files involved

| File | Purpose |
|------|---------|
| `app/domains/events/constants/events.ts` | Event list (date, title, LinkedIn URL). Edit directly. |
| `app/domains/events/types/events.d.ts` | TypeScript type for an event. |
| `app/domains/events/index.ts` | Barrel export for the events domain. |
| `app/composables/useEvents.ts` | Splits events into upcoming / past lists. |
| `app/components/home/modules/events.vue` | Main Events section layout. |
| `app/pages/index.vue` | Home page composition. |
| `app/domains/navigation/constants/nav-links.ts` | Header navigation link (`#events`). |
| `i18n/locales/en-US.json` | Generated labels (do not edit directly). |
| `scripts/events-locize-import.json` | Ready-to-import JSON file for Events labels. |

## Structure of an event

Each event in `app/domains/events/constants/events.ts` follows this shape:

```ts
{
  date: '2026-11-15',        // ISO date (YYYY-MM-DD)
  title: 'naKnow at the Green IT Forum 2026',
  linkedInUrl: 'https://www.linkedin.com/posts/nakow_green-it-forum-2026',
}
```

Rules:
- `date` must be an ISO date string (`YYYY-MM-DD`).
- `title` is the human-readable event name.
- `linkedInUrl` is the full URL of the LinkedIn post.

## Required Loco keys

Import `scripts/events-locize-import.json` into Loco to create the following keys:

```json
{
  "home": {
    "events": {
      "title": "Events",
      "upcoming": "Upcoming events",
      "past": "Past events"
    }
  },
  "header": {
    "links": {
      "events": "Events"
    }
  }
}
```

## Option 1: Import a JSON file into Loco (recommended)

1. Sign in to https://localise.biz/naknow/naknow.
2. From the dashboard, click the **upload icon** to open the import wizard.
3. Select `scripts/events-locize-import.json`.
4. Confirm the format: choose **i18next v4** (`format=i18next4`).
5. Select **Asset IDs** as the source and **en** as the target language.
6. Use the merge settings to avoid deleting existing keys.
7. Save and publish.

## Option 2: Edit directly in the Loco dashboard

1. Go to https://localise.biz/naknow/naknow.
2. Select the **en** locale.
3. Add or edit the keys under `home.events.*` and `header.links.events`.
4. Save and publish.

## After updating Loco

Regenerate the local locale file:

```bash
pnpm locales
```

Then build the site:

```bash
pnpm generate
```

## Adding a new event

1. Open `app/domains/events/constants/events.ts`.
2. Add a new object with `date`, `title`, and `linkedInUrl`.
3. Save and build.

The new event will automatically appear under **Upcoming events** or **Past events** depending on its date.

## How past / upcoming is decided

`app/composables/useEvents.ts` compares each event's `date` to the current date when the visitor loads the page:

- Events with a date **today or later** go to **Upcoming events**, sorted soonest first.
- Events with a date **before today** go to **Past events**, sorted most recent first.

The comparison is evaluated once on page load, so a long-running tab will not update automatically at midnight unless the page is refreshed.

## Adding a new language later

If the site supports more languages in the future, translate the same `home.events.*` and `header.links.events` keys in each new locale inside Loco.
